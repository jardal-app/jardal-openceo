## 2. Hallazgos y Observaciones

### [MEDIO / DOCUMENTACIÓN] Conteo erróneo de niveles en `dirname` dentro de `SKILL.md`
- **Archivo**: `skills/operations/crear-proyecto/SKILL.md:30`
- **Código**:
  ```bash
  SKILL=$(readlink -f .codex/skills/crear-proyecto)
  REPO=$(dirname $(dirname $(dirname $(dirname $SKILL))))
  PY=$REPO/.venv/bin/python
  ```
- **Detalle**: 
  El path canónico resuelto por `readlink -f` es:
  `<REPO>/skills/operations/crear-proyecto`.
  Al aplicar 4 niveles de `dirname`:
  1. `dirname $SKILL` → `<REPO>/skills/operations`
  2. `dirname (...)` → `<REPO>/skills`
  3. `dirname (...)` → `<REPO>`
  4. `dirname (...)` → Directorio padre de `<REPO>` (`/home/develop/development/Jardal`)
  
  Esto causa que `PY` apunte a `/home/develop/development/Jardal/.venv/bin/python` en lugar de `<REPO>/.venv/bin/python`. Si un agente ejecuta el bloque literal del paso de Setup, la resolución del intérprete fallará con `No such file or directory`.
  
  *(Nota: El script Python `crear_proyecto.py:24-35` no sufre este problema porque implementa `_bootstrap_core()` buscando dinámicamente `openceo-core` en `here.parents`).*
- **Recomendación**: Reducir a 3 llamadas `dirname` en la línea 30:
  ```bash
  REPO=$(dirname $(dirname $(dirname $SKILL)))
  ```
  o alternativamente `REPO=$(git -C "$SKILL" rev-parse --show-toplevel 2>/dev/null || dirname $(dirname $(dirname "$SKILL")))`.
